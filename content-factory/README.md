# Контент-фабрика Brookclean Trucks

Система готовит, согласовывает и публикует материалы Telegram-канала компании, которая перевозит автомобили автовозами из Владивостока по России. Она строит контент-план, ищет и проверяет источники, пишет тексты и сценарии, верстает обложки и инфографику, монтирует видео из исходников, заказывает ИИ-сцены, проверяет качество, отправляет черновики владельцу в Telegram и публикует только одобренное.

Публикация без одобрения владельца невозможна: это проверяется в коде, в базе (триггеры неизменности версий) и тестами.

## Что умеет

| Функция | Как устроено |
|---|---|
| Контент-план на 7 и 30 дней | Слоты и форматы распределяет код (доли форматов, 30–60 видео в месяц, интервалы, окна публикации); смысл слотов заполняет модель. Повторы тем и призывов отсекаются проверкой. |
| Исследование тем | Поиск Claude (web search) и RSS. Страницы загружаются с защитой от SSRF, из них извлекаются утверждения с дословными цитатами; код проверяет, что цитата есть на странице. Хранятся URL, дата, хеш, цитаты — не тексты статей. |
| Тексты | Посты, статьи, истории по материалам владельца, реклама, опросы, сценарии видео. Сведения о компании — только из утверждённых владельцем фактов. HTML очищается под Telegram. |
| Графика | Шаблоны бренда (Pillow): обложки, вертикальные постеры, чек-листы, маршруты, превью, титры. Логотип, цвета, шрифты, контакты меняются через API. ИИ-иллюстрации (OpenAI Images) проверяются моделью со зрением и помечаются как синтетические. |
| Монтаж видео | FFmpeg: проверка файлов, анализ сцен, чёрных и застывших кадров, тишины; выбор фрагментов; 9:16, 16:9, 1:1; субтитры из расшифровки речи; титры, вставки, логотип; музыка с приглушением под речь; нормализация громкости EBU R128; превью; повторный рендер при ошибке. Всё описывается EDL и воспроизводимо. Исходники не меняются. |
| ИИ-видео | OpenAI Sora или Runway: короткие сцены, бюджет до запуска, асинхронный опрос, проверка файла и кадров, лимит попыток, учёт стоимости. Недоступность сервиса не превращается в «успех». |
| Проверка качества | Длина под лимиты Telegram, орфография (Яндекс.Спеллер), читаемость, цены/сроки/гарантии/отзывы без опоры на факты, превосходные степени, ссылки, повторы, тема, права на материалы, целостность и параметры файлов, субтитры, громкость, пометка синтетики; плюс проверка моделью. Сомнительное — на ручную проверку. |
| Согласование | Telegram-бот: черновик с медиа, карточка проверок и источников, кнопки «Одобрить / Правки / Переписать / Пересобрать видео / Перенести / Отклонить». Доступ только по числовому Telegram ID из базы. Кнопки привязаны к версии. |
| Публикация | Только одобренная неизменённая версия, прошедшая проверки, с найденными файлами, в разрешённое время, без паузы и отмены. Транзакционно, с защитой от дублей и сохранением message ID. |
| Аналитика | Подписчики, реакции, итоги опросов, переходы по отслеживаемым ссылкам; просмотры — через MTProto, если подключён. Отчёты по форматам, расходам, ошибкам и времени производства; рекомендации только по фактическим числам. |
| Бюджет | Лимиты на день, месяц, задачу, число генераций видео, повторы; пороги предупреждений. Резерв до вызова, фиксация факта после. |
| Мониторинг | JSON-логи без секретов, Prometheus `/metrics`, Sentry, `/health/ready`, уведомления владельцу, журнал действий. |

    cli.py           команды factory
  config/            channel.yaml (канал, бренд, расписание, бюджет), pricing.yaml (цены), templates.yaml (шаблоны)
  migrations/        Alembic
  tests/             unit, integration, e2e, fixtures
  docker/, scripts/  точка входа контейнера, установка, резервные копии

Отличия от предложенной в задаче структуры: каталог `orchestration/` объединяет оркестратор, очередь и планировщик (это одна подсистема); `budget/` и `content/` выделены, потому что их используют все агенты; `scheduler` и `workers` — тонкие точки входа процессов.

## Быстрый старт (разработка)

Нужны Python 3.12+, PostgreSQL 16, FFmpeg, шрифты DejaVu, [uv](https://docs.astral.sh/uv/).

```bash
cd content-factory
uv sync
cp .env.example .env    # для разработки: STORAGE_BACKEND=local, ENVIRONMENT=development, свой DATABASE_URL
uv run alembic upgrade head
uv run factory create-user --name "Владелец" --role owner --telegram-id 123456789 --token
uv run factory facts list
uv run uvicorn app.api.main:app --reload       # API и панель: http://localhost:8000/admin/
uv run python -m app.workers.worker             # фоновые задачи
uv run python -m app.workers.scheduler          # расписание
uv run python -m app.workers.bot                # Telegram-бот (polling)
```

Тесты: `TEST_DATABASE_URL=postgresql+asyncpg://user:pass@localhost:5432/factory_test uv run pytest`.

## Развёртывание

```bash
cd content-factory
bash scripts/setup.sh   # первый запуск создаст .env; заполните его и запустите снова
```

Скрипт собирает образ, применяет миграции, проверяет ключи и доступность сервисов (`factory check`), запускает `db`, `api`, `worker`, `scheduler`, `bot` и выдаёт API-токен владельца. API слушает `127.0.0.1:8000` — наружу его публикует обратный прокси с HTTPS (Caddy или nginx), например поддомен `content.<домен>`. Подробности, резервные копии и обновление — в [docs/operations.md](docs/operations.md).

Перед запуском:
1. Создайте бота у @BotFather, добавьте его администратором канала с правом публикации.
2. Узнайте свой числовой Telegram ID (например, у @userinfobot) — он в `BOOTSTRAP_OWNER_TELEGRAM_IDS`.
3. Заведите приватный бакет S3 и ключи.
4. Получите ключи API поставщиков (см. [docs/providers.md](docs/providers.md)).
5. Проверьте сведения о компании: `factory facts list`. Подтверждённые владельцем (контакты, маршруты, сроки) уже утверждены в `config/channel.yaml`; остальные утверждаются командой `factory facts approve <ключ>`. Цены не публикуются (`qa.publish_prices: false`).
6. Загрузите истории перевозок: `factory stories load` (берутся из `config/stories.yaml`).

## Как пользоваться

- Каждое утро планировщик дополняет план на 7 дней вперёд; материалы готовятся за `production_lead_days` до публикации.
- Черновики приходят владельцу в Telegram. Одобрение назначает ближайшее разрешённое время; «Перенести» предлагает свободные слоты.
- Видео: загрузите исходники через API (`POST /api/v1/media`, `purpose=source`, с указанием прав) и привяжите к материалу (`item_id`) или передайте `source_asset_ids` при создании материала.
- Истории перевозок пишутся только по вашим фактам: `/story <что произошло>` в боте.
- Команды бота — [docs/telegram-bot.md](docs/telegram-bot.md); API — `/api/docs`.

## Что проверено и что нет

Проверено автоматическими тестами (134 теста, PostgreSQL и FFmpeg реальные): конвейер от идеи до публикации, правила согласования и запреты публикации, защита от дублей при повторной доставке задач, неизменность версий в базе, бюджет и параллельные резервы, очередь задач, рендер видео FFmpeg, шаблоны, загрузка и проверка файлов, SSRF, RBAC, API, бот, S3 (через moto), резервное копирование.

Внешние API (Anthropic, OpenAI, Runway, Telegram, Яндекс.Спеллер) в тестах заменены двойниками или HTTP-моками; формы запросов сверены с официальными SDK поставщиков. **С реальными ключами система в этой среде не запускалась** — первый запуск с ключами стоит провести на тестовом канале и проверить `factory check`. Docker-образ описан, но в среде разработки собрать его не удалось: доступ к репозиториям Debian и Docker Hub был закрыт сетевой политикой; в CI шаг сборки образа включён.

## Ограничения

- Bot API не отдаёт просмотры постов; они доступны только через MTProto (необязательный модуль, нужен пользовательский аккаунт-администратор).
- Озвучка не генерируется: текст сценария выводится субтитрами. Адаптер синтеза речи можно добавить по образцу `providers/speech`.
- Проверка фактов моделью — не гарантия: всё сомнительное помечается для ручной проверки, а сведения о компании берутся только из утверждённых фактов.
- Доступность API Anthropic и OpenAI зависит от страны и условий поставщиков — до запуска убедитесь, что используете их законно. Адаптеры заменяемы (см. [docs/providers.md](docs/providers.md)).
