# Безопасность

- **Секреты** только в переменных окружения (`.env` с правами 600 или менеджер секретов оркестратора). В настройках — `SecretStr`; процессор логов и Sentry вырезает токены Telegram, ключи API, Bearer-токены, пароли из URL базы и подписи S3. Telegram-клиент не включает URL с токеном в тексты ошибок.
- **Авторизация.** Admin API — Bearer-токены, в базе только SHA-256. Бот — числовой Telegram user ID из таблицы `users`; username не используется для доступа. Неизвестные пользователи получают отказ, попытки пишутся в журнал.
- **RBAC.** Роли: `owner` (всё), `admin` (согласование, публикация, медиа, просмотр бюджета), `editor` (идеи и загрузки, без одобрения), `viewer` (просмотр). Право подтверждать права на материалы — только у согласующих.
- **Публикация** — единственный путь в канал: `publishing/service.py`. Агенты не получают ни токена, ни функций публикации. Условия публикации перепроверяются под блокировкой непосредственно перед отправкой.
- **Загрузка файлов**: лимит размера, тип по сигнатуре файла (не по расширению и не по заголовку клиента), список разрешённых типов, проверка FFmpeg для видео и аудио, потоковая запись во временный файл.
- **Медиа** в приватном бакете; выдача — только авторизованным через API (короткоживущая presigned-ссылка или поток).
- **SSRF**: внешние URL — только http/https на портах 80/443, без учётных данных и внутренних имён; все адреса хоста должны быть публичными (запрещены частные, loopback, link-local, метаданные облака, CGNAT); соединение идёт на проверенный IP с SNI исходного имени (защита от DNS rebinding); каждый редирект проверяется заново; ограничены размер и время.
- **Внешние тексты** (страницы, материалы владельца, правки) передаются модели в теге `<untrusted>` как данные. Код из сообщений и документов не исполняется; FFmpeg вызывается списком аргументов без оболочки.
- **HTML** в постах проходит белый список тегов Telegram; ссылки, которых нет среди разрешённых целей призыва, превращаются в текст.
- **Веб-панель** требует токен, хранит его только в sessionStorage вкладки; CSP `default-src 'self'`, запрет фреймов.
- **Журнал** `audit_logs`: изменения статусов, согласование, пользователи, токены, бюджет, факты, загрузки, пауза.
- **Персональные данные**: переходы по ссылкам считаются без IP и User-Agent; в отчёты не попадают секреты и исходные материалы.
- **Резервные копии** лежат в том же приватном бакете; для разделения прав используйте отдельный ключ S3 только на запись в `backups/`.
