# Brookclean · доставка автомобилей автовозом

Сайт для клиента в формате PWA: открывается по ссылке, ставится значком на экран телефона
(Android — кнопка «Установить», iPhone — «Поделиться → На экран „Домой“»).

Клиент вводит автомобиль (марка, VIN или номер кузова, год, цвет, стоимость) и город, подтверждает
номер кодом из SMS и видит расчёт (тариф + страховка 0,3%), заполняет данные для договора, читает договор и согласие на ПД,
подписывает кодом из SMS (ПЭП) и получает ссылку на трекинг автовоза.

## Устройство

| Папка | Что внутри |
|---|---|
| `shared/` | Города, схема маршрута, сумма прописью, проверка полей — общие для сайта и сервера |
| `server/` | Node.js 22 + Fastify + SQLite (`node:sqlite`). API заказов, подписи, трекинга, менеджера; отдаёт собранный сайт |
| `web/` | React + Vite + vite-plugin-pwa: манифест, иконки, service worker (трекинг открывается и без сети) |
| `deploy/` | Конфиги для VPS: systemd и nginx |

Тарифная сетка и расчёт — только в `server/src/pricing.ts`, в код сайта они не попадают
(сборка `web/` падает, если это случится). Сервер считает цену сам и не доверяет цене из браузера. Кэшбэк партнёра хранится на сервере
и прибавляется к перевозке; в ссылке партнёра только токен (`/?p=…`).
При подписи сохраняется журнал: телефон, время, IP, браузер и SHA-256 данных договора.
Код из SMS живёт 10 минут, 5 попыток ввода, повторная отправка не чаще раза в минуту.
Трекинг `/t/{токен}` показывает только авто, маршрут и положение — без ФИО и телефона.

После подписания клиенту предлагается игра brookcleangame.online. Когда автовоз прибыл, в трекинге
появляется кнопка «Автомобиль получил», после неё — форма отзыва. Отзыв сохраняется у нас и виден
менеджеру; при оценке 4–5 клиенту предлагается продублировать его в 2ГИС, при 1–3 — сообщение,
что отзыв передан руководителю. Если выдачу отмечает менеджер, клиенту один раз уходит SMS со ссылкой на отзыв.

## Запуск для разработки

```bash
npm install
npm run dev          # сервер :3000 и сайт :5173
npm test             # тесты расчёта, API и SMS
```

С `SMS_PROVIDER=console` (по умолчанию) SMS не уходят: код пишется в лог сервера, а в режиме
разработки ещё и показывается на экране подписи.

## SMS Aero

В `.env`: `SMS_PROVIDER=smsaero`, `SMSAERO_EMAIL`, `SMSAERO_API_KEY` (кабинет smsaero.ru → Настройки → API).
`SMSAERO_SIGN` — имя отправителя (например, `Brookclean`) после согласования в кабинете;
пока оно пустое, SMS идут от общей подписи «SMS Aero».

Демо без сервера (одна HTML-страница, API имитируется в браузере):

```bash
cd web && DEMO=1 npx vite build && node scripts/demo-page.mjs ../brookclean-demo.html
```

В демо-странице весь прайс внутри файла: показывайте её лично и не выкладывайте в открытый доступ.

## Защита цен от сбора конкурентами

- **Цена только после входа по SMS.** `/api/quote` отвечает только номеру, подтверждённому кодом
  (cookie на 30 дней). Договор оформляется на этот же номер.
- **Лимиты** (`server/src/guard.ts`, `LIMITS`): до 6 разных вариантов «город + кузов» в сутки на номер и 12 на IP,
  SMS — не больше 3 в час и 8 в сутки на номер, входов — 5 в час и 15 в сутки с одного IP.
- **Капча.** Яндекс SmartCaptcha появляется только при подозрительной активности: третий вход с одного IP за час,
  пятый за сутки или записи в журнале. Ключи — `SMARTCAPTCHA_CLIENT_KEY` и `SMARTCAPTCHA_SERVER_KEY`.
- **Журнал и чёрный список** — раздел «Защита» в панели (право `security.manage`, у владельца есть):
  кто упёрся в лимиты, перебирает города (4 и больше за сутки), подбирает код или не прошёл капчу.
  Номер или IP можно заблокировать: им отвечаем «позвоните нам».

- **Один автомобиль в сутки для обычного клиента** (`server/src/partners.ts`, `CLIENT_ORDERS_PER_DAY`).
  Цену второго автомобиля за сутки сайт не показывает (`/api/quote` отвечает 403), клиент сразу попадает
  на карточку партнёра. Кто хочет больше, заполняет на сайте карточку партнёра с реквизитами компании (ИНН, КПП, ОГРН, адрес, банк,
  БИК, счета, контакт). Менеджер одобряет её в разделе «Партнёры», клиенту уходит SMS, лимиты на расчёты и SMS
  для этого номера снимаются. Заявки, оформленные менеджером, в лимит не входят.

Полностью скрыть цены нельзя: конкурент может один раз оформить расчёт на свой номер. Цель — чтобы собрать
весь прайс было долго и дорого.

## Панель управления — `staff.brookclean-reg.ru`

Панель собирается отдельно (`web/admin.html`) и открывается только на адресе из `STAFF_URL`.
На сайте клиента нет ни ссылки, ни страниц `/admin`, ни кода панели, ни её API. Если `STAFF_URL` пустой
(разработка), панель открывается по `/admin` на том же адресе.

Вход по логину и паролю. Первого владельца создают переменные `OWNER_LOGIN` и `OWNER_PASSWORD`,
остальных сотрудников владелец добавляет в разделе «Сотрудники».

| Раздел | Что внутри |
|---|---|
| Заявки | Таблица: авто, клиент, перевозка, страховка, оплата (кому, форма), рейс, трекинг. Поиск и фильтры |
| Оформить заявку | Менеджер вносит заявку со слов клиента, клиенту уходит SMS со ссылкой `/o/…`, он подписывает сам |
| Рейсы и отчёты | Рейсы и рейсовый отчёт по каждому: машины, путь (видят клиенты рейса), расходы, одометр, закрытие рейса; CSV и Google Таблица |
| Отзывы | Отзывы клиентов, низкие оценки сверху |
| Партнёры | Ссылки с кэшбэком |
| Сотрудники | Добавить, сменить роль или пароль, выключить; таблица прав по ролям |

Роли: владелец (всё), менеджер, бухгалтер (оплаты и отчёты), приёмщик (заявки и рейсы без ФИО и телефонов),
водитель (раздел «Мои рейсы»).

### Водитель и рейсовый отчёт

Владелец заводит водителю логин в разделе «Сотрудники» с ролью «Водитель». Водитель входит на `staff.brookclean-reg.ru` с телефона и:

- создаёт рейс: город назначения, автовоз, дата, одометр при выезде (номер R-NN присваивается сам, рейс записывается на него);
- грузит подписанные машины, чей город на маршруте, и отмечает, где сейчас автовоз;
- вносит расходы: топливо (с литрами), платные дороги, стоянки, ремонт, мойку, суточные, прочее;
- закрывает рейс, указав одометр по возвращении; пробег считается сам.

Водитель видит только свои рейсы, без сумм договоров и с сокращёнными ФИО. Закрытый рейс водитель уже не меняет,
открыть его снова может менеджер. Менеджер может создать рейс сам и выбрать водителя из списка.
Права и роли — `shared/src/staff.ts`, разделы — `web/src/admin/modules.tsx`: новый раздел = компонент + строка в списке + право.
Все изменения пишутся в журнал (`audit`).

### Рейсовый отчёт в Google Диск

1. console.cloud.google.com → новый проект → «APIs & Services» → включить **Google Drive API**.
2. «OAuth consent screen»: тип External, добавить свой email в тестовые пользователи.
3. «Credentials» → «Create credentials» → OAuth client ID → **Web application**,
   Authorized redirect URI: `https://staff.brookclean-reg.ru/api/google/callback`.
4. Client ID и Client secret — в `.env` (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`), перезапустить сервис.
5. В панели: «Рейсы и отчёты» → «Подключить Google Диск» → войти в Google.

Сайт создаёт папку «Brookclean · рейсовые отчёты» и по каждому рейсу Google Таблицу; она обновляется через
несколько секунд после любого изменения рейса или его машин. В отчёте нет паспортов, ФИО сокращено, телефон
скрыт: Google хранит данные за пределами РФ.

API панели доступно и скриптам: заголовок `Authorization: Bearer $ADMIN_TOKEN` (права владельца).

## Размещение на Reg.ru (brookclean-reg.ru)

Нужен **Cloud VPS** (Ubuntu 24.04, 1 ядро / 1–2 ГБ на старт), а не виртуальный хостинг.

```bash
# на сервере
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo bash - && sudo apt install -y nodejs nginx certbot python3-certbot-nginx git
sudo useradd -r -m -d /opt/brookclean brookclean
sudo -u brookclean git clone https://github.com/todorove001-debug/Brookclean-Ai /opt/brookclean
cd /opt/brookclean && sudo -u brookclean npm ci && sudo -u brookclean npm run build
sudo -u brookclean cp .env.example .env   # заполнить ADMIN_TOKEN и ключи SMS Aero
sudo cp deploy/brookclean.service /etc/systemd/system/ && sudo systemctl enable --now brookclean
sudo cp deploy/nginx.conf /etc/nginx/sites-available/brookclean && sudo ln -s ../sites-available/brookclean /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d brookclean-reg.ru -d www.brookclean-reg.ru -d staff.brookclean-reg.ru
```

В панели Reg.ru у домена — A-записи `@`, `www` и `staff` на IP сервера. PWA работает только по HTTPS,
поэтому шаг с certbot обязателен.

## Распознавание фото — Yandex AI Studio

Фото документов водителя, чеков и повреждений читает Yandex AI Studio (сервер и данные в России).
Запрос идёт только с сервера: `POST /api/staff/recognize` с JPEG. Ключ — в `.env` (`YANDEX_API_KEY`, `YANDEX_FOLDER_ID`),
в коде и в браузере его нет. Без ключа распознавание выключено, поля заполняются вручную.

Модель путает отдельные цифры, поэтому распознанное никогда не сохраняется само:

- **Проверки** (`shared/src/recognize.ts`): контрольная цифра VIN, формат госномера, номеров ВУ и СТС, серии и номера паспорта,
  кода подразделения; даты (нет в будущем, паспорт с 14 лет, ВУ на 10 лет); у чека ФН 16 цифр, ФД и ФП в пределах, ФД и ФП не перепутаны,
  цена литра топлива 30–200 ₽.
- **Второе прочтение.** Номер ВУ, СТС, VIN, госномер, серия и номер паспорта, сумма, ФД и ФП чека модель читает ещё раз отдельным вопросом.
  Разошлись — поле красное, рядом оба варианта.
- **Нижняя строка паспорта** (MRZ) имеет свои контрольные цифры: если она прочиталась, серия, номер, даты и код сверяются с ней.
- **QR-код чека** читается на сервере; ФН, ФД, ФП, сумма и время из него точнее, чем прочитанные моделью.
- **Человек подтверждает.** Фото рядом с полями, ошибки не дают сохранить, сохранить можно только с отметкой «Сверил поля с фото».
- **Повреждения** — только предложения: фото проверяется целиком и по четырём частям (мелкие сколы и бордюр на диске видны лишь в увеличении),
  каждое найденное повреждение водитель подтверждает или отклоняет.

Сейчас в панели по фото вносится чек в рейсовом отчёте («Чек по фото»). Документы водителя и акт приёмки с повреждениями
пока есть только в прототипе; при переносе в панель они используют тот же `/api/staff/recognize` и тот же экран сверки.

## Кабинет приёмщика — раздел «Приёмка»

Заявка сразу попадает приёмщику с данными клиента и автомобиля. Приёмщик снимает 35 фото по подписанным ячейкам
(кузов, диски, дверные проёмы, салон, багажник, мотор, VIN) и 6 видео до минуты, заполняет акт по шаблону
«Акт приема передачи» (ПТС, ключи, условия осмотра, схема кузова с кодами A1–X) и даёт подписать акт пальцем на экране:
сначала «Сдал», потом «Принял» — раздел закрывается.

- **ИИ (Yandex AI Studio)** проверяет наружные фото и предлагает дефекты красным пунктиром. В акт они попадают,
  только когда приёмщик нажал «Согласен»; пока есть нерешённые находки, акт не подписать.
- **Подписи сбрасываются** при любом изменении раздела после подписи. В подписанном акте снять отметку дефекта может
  только менеджер, с комментарием: подписи остаются, отметка видна в истории как снятая.
- **Фото и видео — в S3** (`S3_*` в `.env`). Телефон грузит файл прямо в хранилище по подписанной ссылке, фото
  сжимаются до 2000 px. Без S3 в разработке файлы живут в памяти сервера, в продакшене загрузка выключена.
- **Перегруз в Новосибирске.** Менеджер в «Заявках» ставит галочку «перегруз Новосибирск», первый рейс до терминала
  и рейс дальше. У приёмщика терминала (площадка выбирается в «Сотрудниках») списки «Прибывают на перегрузку»
  и «На площадке». Акт сквозной: приёмка во Владивостоке → приём на терминал (сдаёт водитель) → погрузка с терминала
  (принимает водитель второго рейса). У каждой передачи свои фото, видео и подписи; дефекты общие, цвет — передача.
  На перегрузе ИИ сравнивает фото с тем же ракурсом прошлой передачи и ищет только новое.
- **PDF акта** по шаблону — кнопка «Скачать акт PDF» в подписанном разделе.

## Автопарк: водители, рейсы, отчёт, доставки

- **Водители** (`server/src/fleet.ts`, раздел «Водители»): реестр своих и наёмных водителей с тягачом, прицепом, компанией и
  данными документов (паспорт, ВУ, СТС тягача и прицепа) по фото. Фото документов не хранятся, только поля. Импорт из Excel
  (`.xlsx`, читается в браузере, повторный импорт не дублирует). Водитель видит и дополняет свою карточку.
- **Рейс на 8 мест**: девятую машину не поставить; «Сформировать рейс» фиксирует состав. Водитель из реестра подставляет тягач,
  прицеп и перевозчика. Блок «Распределение машин» предлагает подходящие рейсы, в том числе от терминала перегруза.
- **Рейсовый отчёт**: аванс, остаток или перерасход, водитель сдаёт отчёт, менеджер принимает или возвращает с комментарием.
  Сданный отчёт водитель не меняет. Выручка рейса при перегрузе делится по километрам плеча.
- **Стоянка**: раздел «Стоянка и заявки», вкладки «Стоянка Владивосток» и «Терминал Новосибирск» — машины, которые ждут рейса.
- **Таблица доставок** по рейсу как лист «Рейс» (раздел «Доставки», рейсы вкладками): движение, страховка СВ 40% / ИП 60%,
  № полиса, оплата, «Обратка».
- **Регистрация** водителя или приёмщика на странице входа; менеджер подтверждает заявку, вход по телефону.
- **Кабинет партнёра** (роль «Партнёр»): партнёр сам делает ссылку со своим кэшбэком (до 100 000 ₽), видит расчёт цены для
  клиента и «Мои клиенты» с суммой кэшбэка. Ссылки и заказы связываются по имени: имя сотрудника-партнёра должно совпадать
  с именем партнёра в ссылках менеджера (например «Роман · Монстеркар»).
- **Telegram**: менеджеру приходит сообщение о каждом подписанном договоре. Нужны `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`
  в `.env`, без них ничего не отправляется.
